Why this is hard

Searching on money the customer doesn't have yet.

The design

The leasing model runs inside the database

Ranking by monthly rate means you cannot fetch twenty cars and price them afterwards — you would be filtering on the wrong key. We compiled the model into DuckDB macros generated from the same constants as the Python model.

45,611 rows ranked in 70 ms
The obvious risk

Two engines, one number

A model that quotes one rate and bills another is the worst thing this system could do. Sixteen parity tests — every term × every mileage tier — assert the SQL and the Python agree on real listings.

Agreement to the cent
On stage

It cannot offer a car it can't quote

Every leasing eligibility rule also runs in SQL, so search only ever returns cars the quote step will accept. “Actually, that one can't be leased” is not a thing that can happen here.

Dealer, age, mileage, down payment — all pre-filtered

Thirty seconds each, no more. The point of this slide is that the headline feature forced a real architectural decision, and that we knew what its failure mode was and tested for it. If they only remember one thing: the rate is a SQL predicate, not a post-processing step.

Backup · answers we have ready
Are those leasing rates real?The model is ours and deliberately plausible, not a lessor's book. The structure is real — depreciation plus finance on the bound capital, residual from an age-decay curve. Swapping in real pricing is a config change, not a rewrite.
What's the latency?Search is 70 ms. The tool session opens while the visitor is still saying hello, so the first question pays no handshake. What you hear is the realtime model, not our stack.
What if it makes something up?It has no listing knowledge to fall back on. Every fact comes from a tool, and the rate a customer hears comes from one function — the same one that writes the email.
Why one agent and not five?The journey is one conversation. Every handover costs a turn of latency and a chance to lose the thread. The persona registry is still there — we chose not to use it.
How would this scale?The tool server is stateless over a read-only dataset, so it scales horizontally. The conversation is the only state and it dies with the room.
What would another day buy?Live inventory, real lessor pricing, and a proper handoff to a human at the contract step. Not more agent features.

Whoever is not speaking watches for these. The chief engineer takes the first three, business case takes the last three. Nobody answers a question with a number the tools did not produce.
